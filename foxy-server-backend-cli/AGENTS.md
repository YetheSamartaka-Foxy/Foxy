# Server CLI agent notes

- Load `../conventions/CLI_CONVENTIONS.md` before changing command behavior, flags, generated output, or automation contracts.
- Load `../conventions/EXAMPLES_CONVENTIONS.md` when generated `repo.json` or `repository_space.json` shape changes.
- Preserve `appUpdateUrl` passthrough from config to generated `repo.json`; CLI `--app-update-url` wins over config.
- `dlcContent` in config.json accepts the object form or a list of codes and is written verbatim into `repo.json`; unknown codes are a parse error.
- `create` prints the server launch line last; keep it a single grep-able line for wrapper scripts. `mod_line::build_server_launch_line` picks the shape from the config's `game` (`types::RepoGame`, default `arma3`): Arma 3 gets `-mod=` (Creator DLC codes, then enabled non-client-side mods, prefixed by `--mod-line-prefix`); Arma Reforger gets `-addonsDir <prefix or .> -addons <id,...>` with ids from each mod's `.gproj` (GUID, project ID, `ServerData.json` id, folder name), the same resolution order as the client's `core/game/reforger.rs`. `mod_line::game_config_warnings` flags Arma-only keys (`dlcContent`, `clientSide`) in a Reforger config. `new --game reforger` writes the Reforger template (`config::template_config_value`), and `repo.json` carries `game` only when it is not `arma3` so Arma 3 output is unchanged.
- `.pak` files (Enfusion PAC1: `FORM` + `PAC1` magic, `FILE` chunk tree) hash into `$$HEADER$$`/entry/`$$GAP:n$$`/`$$END$$` parts through `foxy_formats::Pac1Format`; the layout matches the public PakInspector `pak.ksy` spec. No game switch is needed for hashing.
- Key collection (`src/keys.rs`) is opt-in via `--collect-keys`/`--keys-output`/`--additional-keys`, flattens by file name, and must stay non-destructive toward the destination folder. `create-space --per-repo-keys` reuses it per repository into `<repo>/keys`.
- `create-space` (`src/space.rs`) wraps the `create` pipeline over a space config (`examples/json/server_backend/space.json`) and writes the client-facing `repository_space.json` (`Name`/`Address`/`Requiered` entries, images hashed with SHA-1 like `repo.json`). Manifest writers shared by both commands live in `src/artifacts.rs`; `hash::process_mods` takes `Option<&Path>` so `pool`/`link` layouts can hash without copying. Keep the layout invariants: shared mod names must hash identically across repositories, real directories are never replaced by symlinks, and `--layout link` stays behind `--yes`.
- `discover_files` skips a root-level `foxy_addon.json` so a folder published in place (or a previous output reused as a source) does not hash its own manifest.
- `build.rs` bakes `FOXY_GIT_HASH` for `--version` (`src/build_info.rs`); the desktop app has the same pair, keep them in step.
